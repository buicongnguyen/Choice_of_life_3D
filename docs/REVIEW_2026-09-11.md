# 0.1.1 — detailed design, code review, and logic review

Scope: `Choice_of_life_3D`, based on clean commit `8ee8bb7`. The original 2D repositories were not modified. The design was written first in `GAME_DESIGN.md`, including exact UI behavior, numeric map/movement contracts, all twelve stage activities, save rules, and a separate future-work list.

## Findings and fixes

| Area / severity | Finding | Implemented correction |
| --- | --- | --- |
| Navigation / high | Rounding a valid floor tap into an occupied grid cell could reject it. Grid endpoints/edges did not guarantee a clear connecting segment. | Added pure `navigation.ts`: exact endpoint connections, swept collision checks, reachable grid search and safe path smoothing. |
| Save resume / high | Old positions could be accepted inside furniture or just outside the runtime bounds, preventing useful movement. | Recover to nearby free floor on room load, then persist the corrected coordinates. Valid positions remain unchanged. |
| Chapter load / high | Blur/pagehide during asynchronous room loading could overwrite the next stage's spawn with the previous room's location. | Never copy renderer coordinates into state while loading. Unrelated click actions are blocked during loading; a blur-triggered pause survives load completion. |
| Map geometry / medium | Plant pots, toy blocks, planters and tree trunks were visible but had no ground collision. | Added their measured footprints to collider metadata and the Blender generator. No mesh changes or unnecessary binary re-export. |
| Grounding / medium | Garden stepping stones were treated as a continuous elevated strip; cats, rewards and arch used a fixed height. | Shared surface function distinguishes stone gaps, rugs, path and grass. Other ground anchors use the local surface. |
| Gait / medium | A held direction animated the feet even when blocked; fixed time cadence did not track actual travel. The seated baby swung adult-style legs. | Gait phase follows actual distance and stage scale. Blocked movement stops limb swing; seated baby keeps legs in place with small scooting arm motion. No root scaling or sway added. |
| Touch / medium | Releasing a second pointer stopped the first pointer's pad movement. Canvas release/drag could accidentally become a tap or leave a stale press. | Single pointer ownership, matching release/cancel handling, canvas pointer capture, and a 10-pixel tap threshold. |
| UI / medium | Modal background controls remained available; focus could be lost after rebuilding HTML. | Inert background, focus containment/restoration, retained button tab stops, and E interaction even when a HUD button has focus. |
| Layout / medium | Fixed dialogue reservation could mismatch real content height. Small screens hid earlier-choice context. Progress crossed the location subtitle. | Measure header/dialogue bounds, scroll long choices, retain context, separate progress from subtitle, and hide the redundant objective while reading. |
| Control size / medium | Desktop pad targets were 40 px. | At least 44 px in all supported layouts. |
| Save validation / medium | Noncanonical IDs, duplicate hazards, mismatched/duplicate memories and malformed effects could survive parsing. | Validate canonical records and memory-to-activity correspondence; restrict hazards to their actual chapters. Preserve legitimate 0.1.0 save prose. |
| Story order / medium | Dad referred to an existing partner even when spoken to before introductions; university intro implied a mandatory order. | Home choice explicitly allows planning a future partnership; education text supports either adviser order. No new progression gate. |
| Activity clarity / low | An apple was called a water bottle; discovery memories were identical; optional activity count was invisible. | Corrected misleading reward labels, chapter-specific discovery memories, optional count, and a Money/security explanation. |
| Feedback / low | A penalty at score zero said “full”; hazard notice always claimed −3; save status could remain stale after failure. | Exact clamped notices, “at minimum” wording, live save status and truthful title/pause warnings. |
| Release / low | Release version was hardcoded separately from package version. | Release metadata reads the package version; package and lockfile updated to 0.1.1. |

## Logic review across every stage

Reviewed all twelve chapter definitions and all three options per encounter. Confirmed prior-chapter completion gates, two encounters per chapter, optional discoveries, fact-derived profession, late-life ending guard, and idempotent activity resolution. Either encounter order remains supported. School peers use the stage scale; parents/teachers remain adults. Identity does not gate a career or alter scores.

The three complete-life choice-policy traces exercise all 72 choices through the pure transition/save rules. Every room family connects the spawn, both people, all three discoveries, and the exit. The apparent “single best score” issue is not resolved by imposing punitive gates: forgiving capped outcomes remain intentional and are documented as a balance limitation.

- Portrait 390×844 and 320×568, plus landscape 844×390: context visible, no horizontal overflow, and non-overlapping scene/dialogue regions. Screenshots reviewed under ignored `docs/captures/refinement-*.png`.
- Follow-up source review corrected a focus-restoration tab-stop regression and subtitle/progress overlap before release.

The initial 0.1.0 full-life browser run remains recorded separately. This patch used targeted browser checks and complete-life pure logic checks, not another long full-life browser traversal. Mobile checks use Chromium emulation, not physical-device or Safari certification.

## Remaining design work

This is still a compact story/exploration game, not an AAA production. Campus and school share room geometry; activity items are symbolic; profession wardrobes and partner-specific conversation arcs remain limited. Mobile landscape dialogue leaves a small overview of the room. Saves are local to a browser. Richer activities, character acting, accessibility beyond keyboard/Explore, career art, and performance on low-end physical devices remain follow-up work in `GAME_DESIGN.md` section 10.

## Release procedure

Commit this reviewed change set, push `main` using `git@github.com:buicongnguyen/Choice_of_life_3D.git`, let the Pages workflow build/deploy, then compare live `release.json` with the pushed SHA. A successful workflow and matching live release are required before calling deployment complete.
